# 时间紧张情况下的执行顺序

首轮直接使用20个开发seed（1–20），k=8、隐藏4个、三种掩码、三个时长、四种模式。不设4seed探索批次，不根据中途结果决定保留哪些条件。

## B 与 C 的具体行动

B先按 [B_DELIVERY_CHECKLIST.md](B_DELIVERY_CHECKLIST.md) 提交第一包（实现/验收/smoke），再按验收结论安排第二包（正式数据）。正式批处理由C主导、B可代跑，B必须提供完整生成与读取程序。

1. **B：先接输入适配，再实现群体接口；A并行核对定义。**按A_B_INPUT_INTERFACE.md处理实际网格、空输入、熵和方向有效性，先跑G15；随后完成固定总权重、drop-normalized、hold真实缓存、完整检查点续跑和逐步导出。禁止仅以旧fixed-total开关冒充已实现。A补充旧依赖来源说明，不要求A补跑群体实验才让B开工。
2. **B：短时合成测试和seed1端到端smoke；C复核。**按ACCEPTANCE.md覆盖边界、四分支T=0、共同前缀、连续/续跑等价及隐藏真值隔离。它们检验软件，不是另一个小规模科学pilot。测试不能因赶时间跳过。
3. **C：固定实际实现SHA和测试记录，生成执行配置；B提供运行环境信息。**本目录已提供560行RUN_MANIFEST.csv和80行T0_TEST_MANIFEST.csv，它们是计划键，不是已完成结果。T=0可以在每seed正式分叉之前作快速门槛验证；任一失败暂停该批，保留日志并排查系统性影响。
4. **C主导批处理，B可代跑。**20个基线各只跑一次，200步共同前缀各只跑一次；每seed共享fresh参考，三个掩码和全部时长复用冻结检查点。验证通过后可按seed并行，worker数由实际内存决定，所有独立流可复现。先完成每seed的完整配对集合，再继续下一批，避免只跑“看上去有效”的条件。
5. **C边收边验数据，全部齐后统计。**可随完成状态核查文件/哈希/字段，不因中途科学结果修改方案、提前停止或补挑seed。20seed整组配对bootstrap，结果仍是开发集探索性证据。

## 规模与计算量

- 每seed：1条fresh + 3掩码×3时长×3非fresh = 28条；20seed共560条。
- T=0：20seed×4模式=80条软件测试，不计入560条。
- 基线检查点20个，事件前检查点20个；每条实验仍导出600步记录和601帧状态。
- 若复用共同前缀，科学批次需要20×6200 + 560×400 = **348,000个群体更新步**，不含验收/离线评估/写盘；不复用前缀则20×6000 + 560×600 =456,000步。计算量不等于实际运行秒数。
- 同状态离线回放不推进群体动力学，不作为额外闭环轨迹或样本；仍需记录计算与存储耗时。
- 不在首轮增加k扫描、噪声、KF、距离衰减、另一套幅值制度。这些会成倍扩大工作，且难以快速归因。
