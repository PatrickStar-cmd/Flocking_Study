## 2. 分两次交付，不要等560条全部跑完才交代码

**第一包：实现与软件验收包，B负责，C复核。**

- 固定代码SHA、依赖路径/哈希、MATLAB版本、配置、运行命令，以及导出数据的读取示例。
- G1–G15测试脚本与结果。tests.json逐项写test_id、配置/seed、命令、PASS/FAIL/NOT_RUN、最大差值/计数、容差及日志路径；不能只给一句“全部通过”。不适用项须说明原因，由C核对，不得静默略过。
- seed1、目标N=20/M=100配置下至少一个完整端到端smoke，明确所用mask和d；包含fresh及三条干预分支、两级检查点、同状态回放、完整字段、由逐步数据生成的摘要。smoke不加入科学样本增量。
- 目标配置的T=0测试能力；20seed×4模式的80条T=0运行记录最迟在各seed正式分叉前补齐。第一包尚未完成的seed须标NOT_RUN，不能据少数测试宣称80条已通过。
- 给出实测smoke耗时、峰值内存（若无法测量须注明）、拟用worker数；不得凭估计保证整批耗时。

**第二包：正式开发集数据包，C主导调度，B可代跑。**

第一包经C复核、实现SHA与协议SHA固定后才可运行。B必须提供可生成第二包的程序；560条并非默认要求B独自运行。若B代跑，按下节完整交付数据；若C运行，C保管相同数据包，B负责接口缺陷修复。未验收时不得为了赶进度先生产整批数据。

## 3. 正式数据必须包含什么

原始MAT保留双精度；CSV只作摘要；JSON保存配置、测试及审计。允许无损压缩或跨文件引用，但必须有读取器能还原完整逻辑数组。

| 数据 | 必须内容 | 数量/时间要求 |
|---|---|---|
| 运行索引 | run_id、seed、mode、mask_rule、duration_steps、reference_id、文件路径、status、错误/缺失原因 | 560个唯一计划键；完成/失败均登记，不静默删除 |
| 参考与干预 | 20条fresh；每seed三mask×三d×三干预模式 | 540条干预，共560条；共享fresh不得重复计样本 |
| 检查点 | 位置、航向、u、alpha、目标ID、缓存/年龄、RNG/驱动索引、配置/代码哈希 | 20个6000步末、20个6200步末；含最后合法观测时间戳 |
| 状态 | 每个体位置和航向，最终神经状态 | 每轨迹j=0…600，共601帧状态；末态u必存 |
| 群体响应 | j、绝对步号、时间、phase、GO、LO、周期平均对距、最近距离及其单位/归一化规则 | 每轨迹600步，禁止只存均值或稀疏81帧 |
| 个体输入指标 | k_selected/k_fresh/k_active、A、Mass、峰值、z1/z2实虚部及模、主方向/有效标记、最大空隙、weightEntropy、no_input、normalization_unavailable | 每步每个体；另存神经质量、bumpConcentration、原始解码值及分析用角/有效标记 |
| 有向边 | observer/target ID、selected/hidden/fresh/active、observed/last/injected bearing、weight、age | 每步；隐藏observed为NaN，真值不混入观测 |
| 掩码 | S_i/H_i/剩余ID、最后合法方位、随机流、tie规则、三集合R1/R2/最大空隙 | 每seed三规则、每个观察者；跨T/模式共用 |
| 输入场 | 实际injected场、该分支自身fresh oracle、对应alpha | 每步均为M×N；本轮100×20；600步逻辑形状可为100×20×600 |
| 同状态回放 | fresh参考轨迹每个缺失时刻的四候选场、输入误差、mask/cache引用 | 每seed/mask/d保存d步；与自身oracle分开，不能计为额外闭环样本 |
| 评估真值 | 分支自身真实方位/周期距离及步初时间戳 | 独立评估通道；足以复算输入误差，不回流控制器 |
| 摘要 | 每seed/mask/d/mode/窗口的主次响应、reference_id、窗口边界、配对差值 | 从原始数据生成；不按560行强行限定摘要行数 |

神经场u不强制每步常规存盘，但G4/G5必须逐步比较；完整检查点和最终u不能省略。空间不足先无损压缩，不能自行降采样。数组维序、角度单位、时间单位、NA编码、非选中边占位、GO/LO和距离公式及对应代码位置必须写入数据字典。JSON用null表示缺失，MAT/CSV的NaN约定显式记录。

## 4. 文件包与C验收方式

新目录 `effective-social-input/results/sq1-fourbranch-pilot-v1-<run_id>/` 至少包含：

- README.md：入口命令、证据等级、文件关系、已完成/失败状态。

- 配置快照、协议版本或内容哈希、RUN_MANIFEST.csv、T0_TEST_MANIFEST.csv及实际运行状态表。
- 两级检查点MAT、原始逐步MAT、同状态回放MAT（可分片；索引必须可定位）。
- summary.csv及其生成脚本、字段与数组维度字典、最小加载示例。
- tests.json、测试脚本、smoke/正式运行/失败日志、SHA256文件清单（不要求清单自包含自身哈希）。
